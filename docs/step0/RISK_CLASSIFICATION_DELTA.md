# RISK_CLASSIFICATION_DELTA.md — inference-tuning 风险分级增量

> 状态：**草案 / 待确认**
> 基线：`~/.ai-infra/config/risk-classification.yaml`（serving 固化、你已确认）
> `[verified]` 基线实测内容：沙箱映射 `R0/R6→none`、`R1→process`、`R2→container`、`R3/R4/R5→vm`；

> 本文只写**调优插件相对基线的增量**。基线未变的部分（R0–R6 定义、8 类资产、确认 TTL、headless 语义）原样沿用，不重复。

---

## 1. 结论先行：调优插件的风险画像与另两包**根本不同**

| | inference-serving | inference-quantization | **inference-tuning** |
|---|---|---|---|
| 它动什么 | **新建**端点 | **新建**量化产物目录 | **就地改一个正在跑的服务** |
| 失败后果 | 新服务起不来（旧的没动） | 产物不可用（旧的没动） | ⚠ **原本可用的服务被改坏** |
| 可逆性 | 不需要（新建） | 删目录即可 | **必须有可靠回滚，否则服务停摆** |
| 时间尺度 | 分钟 | 分钟 | 分钟～小时（多轮测量） |
| 资源占用 | 一次性 | 一次性 | **反复重启 + 长时占 GPU** |

**一句话**：serving 与 quantization 都是"**增量**操作"，tuning 是"**变更**操作"。
这一条决定了本增量里最重要的一档新风险 —— **回滚失败本身是一个独立风险档**。

## 2. 新增操作的定档

| 操作 | 档 | 沙箱 | 涉及资源 | 理由 |
|---|---|---|---|---|
| 读端点/模型/DCGM 指标（诊断） | **R0** | 无 | — | 纯只读。`inference_tuning_diagnose` 走这一档 |
| 墙诊断与理论上界计算 | **R0** | 无 | — | 纯函数计算，不碰环境 |
| 实测可达带宽微基准 | **R2** | 容器级 | `gpu:write`（短时） | 要真跑 GPU kernel 才能拿到"实测可达"，**不得用规格书峰值代替** |
| 经 serving 部署调优专用端点 | **R2** | 容器级 | `gpu:write`、`port:bind` | **借用** serving 的 deploy（风险所有权仍在 serving） |
| 应用一组候选参数（重启端点） | **R2** | 容器级 | `gpu:write`、`port:bind` | 主操作。参数含并发/显存/batch/投机预算 |
| 性能闭环测量（多轮、多请求） | **R2** | 容器级 | `gpu:write` | 长时占用；必须过测量完整性四闸 |
| 精度回归（前后各一次） | **R2** | 容器级 | `gpu:write`、`model:read` | 容器内直算 NLL/perplexity；含测量成立性判定 |
| 写调优注册表 + 报告 | **R1** | 进程级 | `state:write` | 只写自有状态文件 |
| **自动回滚到上一配置** | **R2** | 容器级 | `gpu:write`、`port:bind`、`state:write` | 见 §4 —— 回滚失败是独立风险 |
| 拆解调优端点并验证无残留 | **R2** | 容器级 | `gpu:write`、`port:bind` | 沿用 serving 的 `teardown`（含 `no-managed-residual` 校验） |
| **算子级改动**（若 S3 之后纳入） | **R3** | **VM 级** | `gpu:write`、`disk:write`、`model:read` | **本机 VM 沙箱不可用（§5）→ 一律拒绝**，除非你显式授权降级到容器级 |
| 改宿主 OS / 固件 / HDK / 内核 | **R6** | — | — | **一律拒绝**（`[claimed]` 你在 2026-09-17 有明确指令） |
| **改变主模型既有量化格式** | **R6** | — | — | **硬排除**，见 §3.1。不是优先级问题 |
| 修改 `dsh-tuning-engine` / `inference-serving` / `inference-quantization` 文件 | **R6** | — | — | 项目边界硬约束 |

## 3. 新增的硬门禁（调优特有，四条）

### 3.1 主模型量化格式**硬排除**（不是优先级）

```
规则：调优不得改变主模型既有的量化格式（含 linear_attn 的 FP8 → NVFP4 这类"改格式"优化）
判据：候选参数集若包含任何 quantization / kv-cache-dtype / 权重精度类条目
      → E_QUANT_FORMAT_FORBIDDEN，直接拒绝，不进降级链
      （终态失败：换参数解决不了，因为这是目标函数之外的约束）
落盘：拒绝记录写审计；`not_provided` 能力清单里显式声明"不做量化格式变更"
```

**为什么写成硬门禁而不是"默认不开"**：默认值可以被一次调用覆盖，硬门禁不能。
你原话是"是硬排除，不是优先级问题"。

### 3.2 阈值必须外部提供（沿用 quantization 已固化的口径）

```
max_accuracy_drop_pct / min_perf_gain_pct：
  调用方传入 > ~/.ai-infra/config/gates.yaml > 两者都无 → E_THRESHOLD_NOT_PROVIDED
不猜默认值。调优插件不能自己定"可以掉多少精度"然后自己签收。
```

### 3.3 测量成立性（性能侧四闸 + 精度侧三条）

| 侧 | 闸 | 判据 |
|---|---|---|
| 性能 | ① 聚合口径已声明 | 必须显式声明 `peak/mean/median/p95/expected`，未声明即拒 |
| 性能 | ② 预热闸 | 重启后 ≤ 3 min 的窗口不是稳态（原引擎实测：TTFT_p99 ≈ 10 s 会塌陷） |
| 性能 | ③ 时滞对齐 | 服务端事件与 GPU 执行须做时滞扫描（实测差 ~150 ms） |
| 性能 | ④ 统计出处 | 声称"有提升"必须走 `APPROVED_ESTIMATORS` 白名单 + Fisher 精确检验 |
| 精度 | ⑤ 均匀输出签名 | `\|meanNll − ln(vocab_size)\| ≤ 1e-4` ⇒ 测量不成立 |
| 精度 | ⑥ 无区分力 | 前后两次 `meanNll` **逐位相同** ⇒ 测量不成立 |
| 精度 | ⑦ 与输入无关 | 逐条 `meanNll` **极差 = 0** ⇒ 测量不成立 |

⑤⑥⑦ 与 `inference-quantization` 同构（Phase 1 已固化）；①②③④ 来自 tuning-engine 的
`measurement-integrity` 四闸。**两侧用同一种落点**：`validity` 证据块 + 独立纯函数判定。

### 3.4 端点所有权：只动自己建的

```
调优只允许操作"经 serving MCP 由本次运行自己 deploy 出来的端点"。
不得对已存在的、非本次运行创建的端点应用参数变更
（诊断 R0 允许只读）。
理由：serving 的注册表里可能有你正在用的服务；就地改它等于越过 serving 的所有权。
```

## 4. 新增风险：**回滚失败**（本增量唯一的"新型"风险）

`inference-tuning` 与原引擎最大的差别是它**就地变更**，因此"改了但回不去"是一个
**必须被单独定档、单独门禁、单独留证**的失败模式。

| 项 | 设计 |
|---|---|
| 定档 | **R2**（容器级）—— 与"应用参数"同档 |
| 前置 | 变更前**必须**先落盘完整可重放的配置快照（`run-spec` 语义：参数 → argv 的完整映射），并校验快照能重放出与当前一致的端点 |
| 执行 | 判定为"未接受"时**自动回滚，不问用户**（这是安全动作，不是危险动作） |
| 门禁 | 回滚后必须**重新测量**并确认指标回到快照状态；回滚不成功 → `E_ROLLBACK_FAILED`，**立即停止整轮调优**并告警 |
| 留证 | 快照、回滚动作、回滚后测量全部进审计哈希链与报告 |
| 强约束 | 在快照落盘**成功之前**不得应用任何参数变更（顺序不可交换） |

**为什么"回滚失败"要单独列**：它不是"调优没成功"，而是"**把一个原本可用的服务留在了坏状态**"。
这两者的严重性不同，处置也不同（前者可以继续试，后者必须停机并叫人）。

## 5. 沙箱可用性（行为验证，不是存在性检查）`[verified]`

| 档 | 需要 | 本机实测 | 后果 |
|---|---|---|---|
| R1 | process | ❌ `bwrap: setting up uid map: Permission denied`（`apparmor_restrict_unprivileged_userns=1`，bwrap 非 setuid） | R1 类操作按**更严的 R2 容器级**执行（与 quantization 同处置） |
| R2 | container | ✅ `docker run --rm --runtime nvidia --gpus all` 实跑成功 | 主路径可用 |
| R3/R4/R5 | vm | ❌ `qemu-system-*` / `firecracker` / `cloud-hypervisor` / `virsh` / `kata-runtime` / `runsc` **六个全未安装** | **算子级改动（R3）在本机一律拒绝** |

## 6. 需要你裁决的点

| # | 分歧 | DSH 建议 |
|---|---|---|
| **①** | 算子级改动（R3，VM 沙箱）本机不可用，是否授权降级到容器级？ | **暂不纳入本轮**。若纳入，需你像 QAT 那样显式授权，且遵守"只影响该模型、容器内先备份 + 隔离验证、绝不碰宿主 OS/固件/HDK" |
| **②** | 调优要不要可以重启**你正在用**的端点？ | **不要**。只操作本次运行自己经 serving 建的端点（§3.4）；对存量端点只做 R0 只读诊断 |
| **③** | "预算耗尽"是否构成停止理由？ | **不构成**（你的长期指令）。停止只有两条：达到物理瓶颈（须附限定条件）/ 你显式中止。这条会写成状态机的终止条件之一并穷举验证 |
| **④** | 自动回滚失败时是否要**主动通知**你（邮件/IM）？ | 建议**要**（本项目已有 `dsh-notifier` 通道）。这是唯一一个"必须叫人"的失败模式 |

## 7. 与基线的一致性声明

- **未新增风险档**：全部操作可映射到既有 R0–R6，无需扩充档位定义。
- **未放宽任何既有门禁**：R6 项（改宿主、改量化格式、改他包文件）在本插件里**只增不减**。
- **确认策略沿用基线**：`tune` / `rollback` / 参数变更按 R2 的 `per-class-once`；
  算子级（若将来纳入）按 R3 的 `always`。
