## 1. 定位、目标与术语

### 1.1 分层定位
- **L0 引擎无关核心**（本文 §3–§8、§12）：状态机、统计、搜索、决策闸、知识库——与具体引擎/硬件无关。
- **L1 引擎适配器**（§9）：vLLM（GPU/Ascend）、SGLang、TensorRT-LLM、llama.cpp 等；提供参数目录、指标映射、执行原语。
- **L2 硬件适配器**（§10）：NPU（Ascend）、GPU（NVIDIA）、CPU——提供资源水位、剖析工具、算子级杠杆。
- **L3 落地形态**（§16）：离线调优沙箱（首选）、生产金丝雀、全局插件/服务。

### 1.2 术语
| 术语 | 定义 |
|------|------|
| 三 KPI | 吞吐（output tokens/s）、TTFT P99、TPOT P99（V1 的"三大指标"统一为这三项；成功率是独立稳定性闸） |
| 黄金基线 | 首次硬基线采集结果，作为不可变参照系 |
| 当前最优 | 本轮调优中评分最高的被接受配置 |
| 决策阈值 | 基于重复测量噪声 σ 决定：t = max(2σ, 3%)，即"至少 2 倍噪声、且不小于 3% 才有意义" |
| 预算 | 单次调优周期最大轮数（默认 30） |
| 耦合对 | 需同时修改才能正确生效的两个或多个参数（如 max_num_seqs × max_num_batched_tokens），可作为复合动作一次执行 |
| 探索轮 vs 利用轮 | 探索轮=随机/全局跳；利用轮=在当前最优邻域内细化 |
| Pareto 前沿 | 多目标下"任何目标改善必然导致其他目标退化"的解集合 |

### 1.3 目标重定义（为什么不是"全局最优"）
在组合 + 非平稳 + 含噪 + 多目标空间上，**严格的全局最优在工程上不可达**（NP-hard + 非平稳 + 测量噪声 + 有限样本）。V2 的工程目标：
1. **预算内近全局最优**：在有限预算内，高概率找到距离 Pareto 前沿 ε 内的解；
2. **统计鲁棒**：所有接受/拒绝决策基于重复测量与噪声阈；
3. **持续跟踪**：上线后通过漂移监测 + 触发再调优，使"当前最优"成为移动目标；
4. **知识热启动**：跨场景复用历史 KB 压缩探索成本。

对外宣发一律用"**预算内近全局最优 + 持续跟踪**"代替"全局最优"。

## 2. 场景矩阵（业务/部署完备性）

### 2.1 部署拓扑
| 拓扑 | 典型场景 | 补充调优杠杆（V1 之外） |
|------|---------|------------------------|
| 单卡单机 | 边缘/小模型/POC | V1 主体 |
| 多卡 TP | 大模型单节点 | TP 大小、NCCL/HCCL、计算-通信重叠 |
| PD 分离 | 超高并发在线 | Prefill/Decode 实例比、KV 传输时延、队列解耦 |
| 多节点 PP/EP | 超大模型 | 流水线气泡、MoE 专家并行、all-to-all |
| 多租户/多模型共存 | 内部平台 | 资源配额、租户 SLO、干扰隔离 |
| Serverless/弹性 | 突发流量 | 冷启动时间、预热、扩容触发、镜像/权重缓存 |
| 边缘设备 | 本地/离线 | 量化精度、小 batch、功耗上限 |

### 2.2 工作负载类型
| 负载 | 特征 | 默认目标函数 |
|------|------|-------------|
| 在线交互（chat） | 低延迟敏感、短轮 | TTFT/TPOT 优先，吞吐为辅 |
| RAG / 长上下文 | 长输入、高前缀复用 | 命中率、TTFT |
| 代码生成 / 长输出 | 长 Decode | TPOT、KV 内存 |
| 离线批 | 延迟不敏感 | 吞吐 + 单千 token 成本 |
| 多轮对话 | 上下文累积 | KV 增长曲线、淘汰策略 |
| 多模态 | 视觉编码阶段 | 编码器算力、共享显存 |

### 2.3 模型族
- dense vs MoE（专家激活、all-to-all 通信）；
- 量化精度（FP8/W8A8/W4A16）：属"质量敏感杠杆"，必须经过质量闸（§11.2）；
- 可投机解码的模型：草稿模型选型是宏观一级杠杆。

### 2.4 目标与约束来源
- **目标**：吞吐 / P99 时延 / 成本（tokens/$）/ 质量 / 稳定性——V2 将成本与质量升格为一类目标；
- **约束**：客户 SLA（硬）、资源上限（硬）、业务偏好（软权）、硬件上限（硬）。

## 3. 方法学总览：闭环 + 形式化状态机

### 3.1 七阶段闭环
```
S0 硬基线采集 → S1 校验 → S2 根因分析 → S3 决策（搜索步）
→ S4 原子执行 → S5 重测 + 闸门 → S6 收敛/交付/知识沉淀
→ （未收敛）回 S2；（收敛）进入上线后持续监测闭环（§12）
```

### 3.2 形式化状态机
| 状态 | 入口触发 | 守卫（Guard） | 出口（Next） | 失败路径 |
|------|--------|--------------|------------|---------|
| IDLE | 启动指令 | 环境 manifest 校验通过 | S0 | env 校验失败 → ENV_FAIL（报告缺项并停机） |
| BASELINE | S0 启动 | 压测工具 + 硬件驱动健康 | S1 | 压测失败 → BENCH_FAIL → 重试×2 → BENCH_FAIL 终止 |
| VALIDATE | 采集完成 | §4.4 校验规则 | S2 | 失败 → 重采（计数，≤3 次） |
| ANALYZE | 结构化 JSON | AI 或确定性规则可用 | S3 | AI 不可用 → 确定性兜底规则（§7.4） |
| DECIDE | 分析完成 | 预算 > 0 且未 SLA 饱和 | S4 | 预算耗尽 / 全部 SLA 饱和 → CONVERGED |
| APPLY | 单条建议（含耦合对） | dry-run 通过 + 拿到并发锁 | S5 | 启动失败/健康检查超时 → 自动回滚至当前最优 → 连续 2 次启动失败 → CONVERGED（标记环境异常） |
| VERIFY | 新一轮压测 | N=3 重复测量完成 | GATE | 压测异常 → 再测 1 次 → 仍异常 → ROLLBACK |
| GATE | 统计计算完成 | §8 决策表 | ACCEPT→S2 / REJECT→S2 | — |
| CONVERGED | §7.5 终止条件 | — | DELIVER | — |
| DELIVER | 报告生成 | — | POST-DEPLOY（在线）/ END | — |
| POST-DEPLOY | 在线监测 | 漂移触发（§12） | IDLE（新轮，轻量） | — |

**并发与安全**：同一服务同一时刻只能有一个调优运行（lease + 锁文件）；所有 APPLY 必须保留上一份"当前最优"配置以一键回滚；生产变更需人审（human-in-the-loop），离线沙箱可免。

## 4. 硬基线与数据采集

### 4.1 可复现性 Manifest（新增）
每次 S0 之前快照：
- **环境指纹**：引擎版本 / 驱动 / CANN（或 CUDA）/ OS / kernel；硬件型号 + 固件 + 驱动；
- **模型指纹**：权重 hash（或 model ID + revision）、量化方法；
- **完整启动参数 + 环境变量**：V1 的"ps -ef | grep vllm"不够，应采集启动脚本与环境变量全集；
- **压测条件**：测试集 + hash、并发/RPS、随机种子、warmup 策略、时长；
- **时间窗与机器 ID**。

此 manifest 随所有后续报告与 KB 条目附带；任一字段变化即视为"不同实验"。

### 4.2 压测协议（新增）
- **Warmup**：丢弃前 W 个请求（默认 200 或 1 分钟）再进入稳态；
- **稳态判定**：保留 V1 的"num_requests_running 达到上限并维持 ≥1 分钟"，并增加"最近 5 分钟输出速率方差 < 10%"；
- **重复测量**：同配置 N=3 次独立运行（每次重启服务以消除顺序效应），上报均值 ± σ；
- **控制变量**：固定随机种子、固定请求到达顺序。

### 4.3 数据采集清单（V1 14 项 + 3 项）
保留 V1 全部 14 项，新增：
| 项目 | 原因 |
|------|------|
| 成本指标（功耗 / 单千 token 成本估算） | 成本感知目标函数（§11.1） |
| 质量分（快速评估子集，§11.2） | 质量闸 |
| 环境指纹（§4.1） | 可复现性 + KB 失效判定 |

### 4.4 校验规则（V1 + 补完）
保留 V1 的 4 项（稳态 / 成功率 ≥99% / 完整性 / 一致性），新增：
- **噪声估计**：以黄金基线 N=3 的 σ 作为本轮噪声参照；
- **环境漂移检测**：每 10 轮用轻量基线复测 1 次；与黄金基线偏差 > 3σ → 环境漂移，冻结调优，优先排查硬件/散热；
- **离群点处理**：单次指标偏差 > 3σ → 丢弃并重测。

## 5. 搜索空间与搜索策略

### 5.1 参数目录（vLLM 种子目录，分层）
| 层 | 类别 | 示例参数 | 影响方向 | 备注 |
|---|------|---------|---------|------|
| T1 | 内存/并发 | max_num_seqs, gpu_memory_utilization, max_model_len, max_num_batched_tokens, enable_prefix_caching | 吞吐/TTFT/内存 | **首选**调整层 |
| T2 | 调度 | scheduler policy, chunked_prefill_size, prefill/decode 优先级 | TTFT/TPOT | |
| T3 | 特性开关 | speculative decoding（draft/n）, quantization, LoRA adapter, KV dtype | 吞吐/质量 | 质量敏感 |
| T4 | 分布式 | TP/PP/EP 大小, PD 分离比 | 吞吐/通信 | |
| T5 | 系统 | env vars（jemalloc, HCCL_*, TASK_QUEUE_ENABLE）, graph mode | 多目标 | |

每个参数记录：类型、范围、步长、影响方向、**耦合对**、状态（Functional / Experimental / Planned，保留 V1 动态发现机制）。

### 5.2 搜索策略
1. **知识热启动**：查询 §13 — 同模型 + 硬件 + 相似 workload hash → 先试历史最佳配置；
2. **粗搜**：从 T1 × T2 随机采样 5 个点（亦可按经验顺序：内存类 → 调度类）；
3. **局部精化**：top-1 点 ± 邻域爬坡（单参数 / 耦合对）；
4. **探索跳**：每 5 次局部轮，做 1 次随机跳（防局部最优）；
5. **耦合对**：已知耦合对可作为复合动作一次执行，仍计 1 轮，但归因为"复合"；
6. **确定性兜底**（AI 不可用时）：规则表
- VRAM > 90% 且算力 < 60% → 降 max_num_seqs；
- 队列持续 > 0 且算力 < 85% → 提 max_num_batched_tokens；
- 命中率 > 30% 且 TTFT 高 → 开 prefix caching；
- 单请求 KV 增长 > N → 开 chunked prefill 或降 max_model_len；
- 多卡 HBM 带宽 > 70% → 检查 TP 切分与通信-计算重叠。

## 6. 统计决策协议

### 6.1 重复测量
- 同配置 N=3（§4.2），上报均值与 σ；
- 黄金基线 3 轮 σ_baseline 作为本轮决策噪声参照。

### 6.2 决策阈值
- 接受阈值 t = **max(2σ_baseline, 3%)**（噪声显著 + 最小有意义变化）；
- 若 σ_baseline > 5% → 压测环境异常（散热/干扰/工具），先修复再调优。

### 6.3 非劣效思想
对"延迟代价换取吞吐"的 ACCEPT-MARKED：若后续 2 轮无新增益则自动回退。

## 7. 多目标决策闸与终止条件

### 7.1 闸门顺序
1. **稳定性闸**：成功率 < 99% → 立即 ROLLBACK（标记"过载"）；
2. **质量闸**：ΔQ > 0.5% → ROLLBACK（除"质量中性参数"外）；
3. **SLA 闸**（有约束时）：任一红线越界 → ROLLBACK + 标记"SLA 违反" + 永久跳过此方向；
4. **资源闸**：VRAM > 硬上限 → ROLLBACK；
5. **统计闸**：|ΔT| ≤ t → 走"无显著变化"路径；
6. **三 KPI 组合决策**（无约束 / 有约束两版本，见 §7.2 / §7.3）。

### 7.2 完整决策表（无约束，吞吐量最大化）
| ΔT | ΔL | ΔP | 动作 |
|---|---|---|---|
| ≥ t | <5% | <10% | **ACCEPT**，继续 |
| ≥ t | [+5%, 10%] | <10% | **ACCEPT-MARKED**，2 轮后复评 |
| ≥ t | >10% | any | ROLLBACK |
| ≥ t | any | >15% | ROLLBACK |
| [−t, t) | any | any | **NEUTRAL**（计入无收益计数） |
| < −t | any | any | ROLLBACK |
| （任意）质量 ΔQ > 0.5% | | | ROLLBACK |

**说明**：补全 V1 决策表所有未覆盖分支；ΔT ∈ [−t, t) 时即使 ΔL 显著改善（吞吐略降但时延降很多）也按"无显著收益"处理，因为无约束目标函数是吞吐。

### 7.3 有约束场景（按客户偏好加权）
SLA 全合规后，按偏好出分：
- **TTFT 优先**：ΔL ≤ 0 且 ΔT ≥ −t → ACCEPT；ΔL > 0 且 ΔT ≥ t → ROLLBACK；
- **吞吐优先**：ΔT ≥ t → ACCEPT（即使 ΔL < 5%）；
- **均衡**：归一化评分 S = 0.5·norm(ΔT) + 0.5·norm(−ΔL)，S ≥ t/2 → ACCEPT；
- **未覆盖组合**（吞吐↓且时延↓）：TTFT 优先 → ACCEPT；吞吐优先 → ROLLBACK；均衡 → 评分裁定。

### 7.4 终止条件（统一"3 轮"以解决 V1 2/3 矛盾）
满足以下任一 → CONVERGED：
- **M ≥ 3**（连续无 ACCEPT 的轮数 ≥ 3）且所有可探索方向已穷尽；
- 预算耗尽（轮数 ≥ 30）；
- SLA/资源饱和（TTFT 余量 < 10% / 资源触顶 / 偏好达成余量 > 30%）；
- 漂移冻结（§4.4） → HALT（非 CONVERGED，需人工介入）；
- 连续 2 次启动失败 → HALT。

**REJECT 默认不留痕**，仅当同一参数累计 3 次 REJECT 才标记"已耗尽"并跳过。

---

## 8. 执行与安全

### 8.1 执行原语
- 修改启动配置（文件） → 重启（或热重载，若引擎支持）→ 健康检查（readiness + 首条推理成功）；
- 健康检查超时 10 分钟 → 启动失败 → 自动回滚至上一份"当前最优"。

### 8.2 失败矩阵
| 失败 | 处理 |
|------|------|
| 参数非法（启动报错） | 回滚 + 标记"当前版本不可行"（更新 KB） |
| 启动 OOM | 回滚 + 更新 KB 中"该卡最大可行参数"上界 |
| 运行 OOM 崩溃 | 回滚 + 触发环境检查 |
| 压测工具失败 | 重试×2 → 本轮 HALT（不应用修改） |
| NPU 挂死 / 硬件异常 | HALT + 告警 + 人工 |
| AI 服务不可用 | 切确定性兜底规则（§5.2.6） |
| 网络分区 / 中间件不可达 | 暂停 + 指数退避 + 告警 |

### 8.3 变更管理
- 所有变更记审计日志（who/when/why/before-after），append-only；
- 生产环境流程：**dry-run → 人审 → 金丝雀（1 实例）→ 观察 30 分钟 → 全量发布**；
- 回滚永远立即可达。

### 8.4 并发控制
- 每服务 1 个调优锁（lease + 锁文件，含 TTL 防死锁）；
- KB 写锁独立。

## 9. 全局插件架构

**结论：可以做成全局插件。** 形式可二选一，亦可并存。

### 9.1 形式 A：独立调优服务/插件（推荐）
- API + CLI + Dashboard；
- 多租户、多服务、横向扩展。

### 9.2 形式 B：Agent 插件（嵌入 AI Agent 框架）
- LLM 作为 ANALYZE 组件；工具即编排器 API；
- **护栏**：所有写操作必须经状态机，不允许 LLM 直写。

### 9.3 组件分解
- **orchestrator**：§3 状态机；
- **search-policy**：§5；
- **gate**：§7 决策表 + SLA + 成本 + 质量；
- **executor**：§8；
- **adapters**（接口契约）：
- `EngineAdapter.getParams()→Catalog` / `applyParams(cfg)→ok` / `restart()→health` / `metrics()→14+3 items`
- `BenchAdapter.run(scenario, cfg)→metrics+noise`
- `EvalAdapter.quickEval(model, subset)→quality score`
- `KBStore.query(model, hw, workload_hash)→candidates` / `record(entry)`
- `HardwareAdapter.waterlevel()→14 items` / `profilingTools()→[tools]`
- `AIConsultant.analyze(json)→Move|None`（swappable，可回退确定性）

### 9.4 安全与可观测
- **RBAC**：read-only / tuning / approval 三级；
- **生产变更强制人审**；
- **审计日志** append-only；
- **数据脱敏**：测试集 PII 不进 KB；
- **可观测**：每轮事件 → Prometheus 指标 + Dashboard + 告警。

### 9.5 实施路线图
| 阶段 | 时长 | 范围 |
|------|------|------|
| P0 | 2 周 | 单机 vLLM-Ascend + 沙箱 POC（状态机 + vLLM 适配器 + 压测适配器 + 决策表） |
| P1 | +4 周 | KB + 报告 + CLI + 质量闸 |
| P2 | +6 周 | 多引擎适配（SGLang/TRT-LLM）+ GPU/NPU 硬件抽象 |
| P3 | +8 周 | 集群级 KB 联邦 + 上线后漂移闭环 + Agent 插件形态 |

## 10. 算子级优化（Phase 3）的泛化

V1 的 Phase 3 强耦合 vLLM-Ascend/CANN。V2 通过硬件抽象层使其泛化：

### 10.1 硬件抽象矩阵
| 层 | Ascend | NVIDIA | CPU |
|----|--------|--------|-----|
| 剖析工具 | MS Profiler / Ascend PyTorch Profiler | NSight / torch profiler | onednn traces |
| 算子杠杆 | MC2 / ACLGraph / HCCL 优化 | CUDA Graph / FlashAttention-3 / TRT-LLM 插件 | onednn graph backend |
| 通信 | HCCL | NCCL | — |

### 10.2 三条铁律（保留 V1）
1. **先分级，再深入**：先 Lite Profiler，必要时才全量；
2. **分阶段，看本质**：Prefill（计算密集）与 Decode（带宽密集）必须分开分析；
3. **改一点，验一次**：原子化修改 + 复用 §7 决策闸（含质量闸）。

### 10.3 Phase 3 终止条件（V1 缺失，补完）
- 杠杆目录所有方向已尝试且无增益；
- 算子级改进 < 1%（低于噪声）；
- 预算耗尽。

### 10.4 决策流程（泛化版）
定位瓶颈（Prefill GEMM / Decode 带宽 / Host 下发）→ 查对应硬件杠杆目录 → 选杠杆 → 原子验证（复用 §7）→ 知识沉淀。

## 11. 成本、质量、安全与合规

### 11.1 成本建模
- **单千 token 成本** = （硬件折旧 + 功耗）/ 输出 token 总数；
- 离线批场景将"单千 token 成本"作为第三目标，报告必含成本列；
- 单位指标与基线对比，作为评审项。

### 11.2 质量护栏
- **快速评估集**：100~300 条分层采样，固定种子；
- **质量敏感杠杆**（量化 / 投机解码 / 算子融合 / 剪枝）变更前后必须评估；
- **ΔQ > 0.5% → ROLLBACK**；
- 常规杠杆（并发/调度类）每轮不必评估，仅收敛后统一评估一次。

### 11.3 安全与合规
- 测试集 PII 不写入日志 / KB；
- API Key 脱敏；
- 审计日志访问控制（与 RBAC 对齐）。

## 12. 持续调优与全局最优逼近

### 12.1 上线后监测
- 三 KPI + 成功率 + 输入长度分布 + 硬件指纹；
- 漂移触发器（触发轻量再调优，仅重做 T1 局部精化，预算 8）：
- 输入长度 P99 偏移 > 30%；
- 流量模式变化（RPS 分布改变）；
- 上游引擎 / 驱动 / 模型版本变更（**触发全量重基线**）。

### 12.2 量化"全局最优逼近"
- 知识热启动后，期望探索轮数 ≈ 无 KB 时的探索轮数 × 衰减系数；
- 预算受约束下，遗憾度（regret）单调下降（informal）；
- **报告交付 Pareto 前沿（3~5 套配置供业务选）而非单点**；
- 多实例：每实例独立调优，结果入集群级 KB；以硬件 + 固件指纹为键；"同指纹权威"解决冲突。

## 15. 最佳实践目录

### 15.1 调优前预检
- 驱动/CANN 匹配；
- 压测工具验证（空载 + 已知配置复现）；
- 多卡网络（IB / RoCE）通；
- 散热正常；
- 备份当前配置。

### 15.2 推荐调参顺序
① 内存可行性（gpu_mem_util, max_model_len）→ ② 并发（max_num_seqs）→ ③ 调度（max_num_batched_tokens, chunked prefill）→ ④ 特性开关（prefix caching, spec decode）→ ⑤ 量化/精度（**经质量闸**）→ ⑥ 算子/通信类（Phase 3）。

### 15.3 红线
- 不改权重；
- 不绕过质量闸；
- 不直接对生产调优（金丝雀 + 人审除外）；
- 不跳过稳态判定。

### 15.4 报告模板
V1 7 节 + 成本 + 质量 + 可复现 manifest + 审计摘要 + Pareto 前沿。

### 15.5 KB 条目模板
模型/硬件/负载指纹 + 目标/约束 + 初始/最终配置 + 三 KPI Δ + 成本 Δ + 质量 Δ + 轮数 + 终止原因 + 经验教训。

## 16. 局限性与未决问题

- **单机视角为主**：集群级成本分摊（多租户配额）待续；
- **Phase 3 算子自动选型**（auto-compile / auto-fusion）尚未端到端自动化，仍需人工 review；
- **AI 分析组件可靠性**依赖底层模型；确定性规则是兜底；
- "全局最优"是预算内近最优，非数学保证；
- **压测 ≠ 生产长期行为**（散热累积、GC、依赖抖动），上线前应做 72 小时浸泡测试作为补充；
- 跨硬件迁移（Ascend → NVIDIA）需重新做宏观调优，KB 衰减系数依硬件距离而定（待量化）。
