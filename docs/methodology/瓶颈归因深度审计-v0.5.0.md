# 瓶颈归因深度审计（dsh-inference-tuner v0.5.0）

> 独立审计 by 子代理，2026-09-02
> 与主审计 `瓶颈归因唯一指向性审计.md` 互补：主审计聚焦**未覆盖的瓶颈类**，本审计聚焦**现有规则的唯一指向性**与**假阳性场景**。

## 矩阵总览

| 规则 | 假阳性场景 | 严重度 | 关键 disambiguator |
|------|-----------|--------|-------------------|
| `ruleVramHardCap` | CUDA workspace 残留；allocator 碎片化；CPU offload 回写 | high | `vllm:model_weights_memory_usage_bytes` + `vllm:kv_cache_memory_bytes` 拆分 |
| `ruleKvHardCap` | 采样点边界假象；prefix cache 撞墙；long-context 单请求 | high | preempt/evict 持续增加；`num_blocks_allocated` vs `total` |
| `ruleSchedulerAdmission` | 冷启动；tokenization wall；GPU step 不同步 | **blocker** | `engine_age_seconds`; `num_waiting_uncached_tokens`; `scheduler_step_p99` |
| `ruleComputeDecode` | chunked prefill；MoE routing；CUDA launch overhead | **blocker** | `tensor_core_util`; `decode_itl_p99` |
| `ruleComputePrefill` | host CPU 限速；PCIe 权重加载；chunked prefill 副作用 | high | `ttft_p99 / tpot_p99`; host CPU |
| `ruleComputeGeneric` | DCGM exporter 挂了；非 NVIDIA 平台 | medium | `vendorProbe`; `dcgmExporterUp` |
| `ruleCommunicationWall` | TP 常态（轻 CV）；DP 路由不均；NVLink 故障；PP bubble | **blocker** | `perCardGpuUtilCV`; `nccl_allreduce_count`; `nvlink_replay_errors` |
| `ruleConverged` | 任何未覆盖桶 + 监控盲区 | high | 必须列出"未观测指标" |

## 7 大未覆盖瓶颈

1. **Host CPU 墙** (A-1, F-4)：tokenizer / Python GIL / asyncio loop；与 GPU 完全解耦
2. **PCIe / Host→Device 传输墙** (A-2)：权重 swap、激活 spill、PD 分离 KV 传输
3. **Disk I/O 墙** (A-3)：MoE 权重 swap、模型加载（`disk_read_bytes`）
4. **Network 入口带宽墙** (A-4)：入口带宽/TLS 终结/网关限速
5. **质量回退软墙** (A-5)：违反 §7.1 闸门 2（ΔQ > 0.5% ⇒ ROLLBACK）
6. **冷启动墙** (A-6)：serverless / 金丝雀场景；稳态 KPI 无法反映
7. **调度器调度延迟本身** (F)：方法论 §5.1 T2 层完全无钩子

## Compute Wall 4 个细分问题

- **D-1 Chunked prefill**：`enable_chunked_prefill=true` 让 Decode/Prefill 共享 batch，DRAM 高不再意味着 Decode
- **D-2 Tensor core 闲置**：FP8 模型下 tensor core 0.18，SM 0.79，看上去是 compute，实际是访存
- **D-3 MoE 路由**：DRAM 高可能是 dispatch 流量，不是 decode 访存
- **D-4 FP8 GEMM ALU intensity**：`gpu_util=0.85` 阈值对 FP8 太紧

## Communication Wall 5 个细分问题

- **E-1 NCCL/HCCL collective 计数与耗时缺失**：无法区分 TP allreduce vs EP all-to-all vs PP p2p
- **E-2 Tensor parallel compute-comm overlap 比**：Nsight 时间线数据未采
- **E-3 EP imbalance ≠ TP imbalance**（详见 D-3）
- **E-4 Pipeline parallel bubble**：per-stage latency 不暴露

## Scheduler Wall 5 个细分问题

- **F-1 Chunked prefill 调度决策**：`enable_chunked_prefill` 参数当前完全无钩子
- **F-2 连续批处理 batch 太小**：违反方法论确定性兜底规则"队列持续 > 0 且算力 < 85% → 提 `max_num_batched_tokens`"
- **F-3 Prefix cache thrashing**：cache 反复失效（数据已采但未用）
- **F-4 Tokenization rate-limited**（同 A-1）
- **F-5 Engine health wall**：NCCL deadlock

## Memory Wall 5 个细分问题

- **G-1 Weight-only wall**：模型装不下 vs KV 撞墙（数据未采但 vLLM 提供）
- **G-2 Activation memory wall**：前向激活，独立于 KV
- **G-3 Swap / CPU offload wall**：`cpu_cache_usage_perc` 数据已采但未用
- **G-4 Memory fragmentation**：allocator 碎片化
- **G-5 CPU cache wall**：一行修复

## 关键发现（不修会被生产坑的）

1. **`service.mjs` 已采集 `cpuCacheUsage`、`prefixCacheHits/Queries`、`liveNumAccel`、`livePreemptions`、`liveEvictedTokens` 五个新指标，但 `bottleneck.mjs` 没有一条规则引用它们**——属于"采了不用"。

2. **方法论 §5.2.6 确定性兜底规则**明确写了"队列持续 > 0 且算力 < 85% → 提 `max_num_batched_tokens`"，但当前 `ruleSchedulerAdmission` 只调 `max_num_seqs`，**与文档冲突**。

3. **`ruleConverged` 没有"未观测指标"的负面清单**——任何 exporter 故障都会被当成"系统已收敛"。

4. **Compute 墙把 SM 利用率当 tensor core 利用率**，对 FP8/量化模型系统性过紧。

5. **Comm 墙只看 per-card throughput CV**，把 TP 常态（轻 CV）、DP 不均（无通信问题）、NVLink 故障、PP bubble 全部混为一谈。
